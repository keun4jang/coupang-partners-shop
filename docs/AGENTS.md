# 살림템 메모장 — 에이전트 자동화 설계도

> 목적: 상품 발굴 → 영상 제작 → 성과 관리를 **역할별 에이전트**로 나눠 자동화한다.
> 이 문서는 코딩 전 "큰 그림"이다. 확정되면 Phase 순서대로 구현한다.

## 0. 지금 이미 되어 있는 것 (중요)

| 기능 | 상태 |
|---|---|
| 공개 사이트(번호검색 + 전체목록, 글자만) | ✅ 라이브 |
| 관리자 페이지 / 텔레그램 봇 | ✅ 라이브 |
| DB (`products` / `video_items` / `click_logs`) | ✅ |
| AI 카피 생성 (`src/lib/ai.ts`, 주부 톤) | ✅ |
| **영상 렌더 워커** (렌더→드라이브 업로드→텔레그램 알림) | ✅ "영상 만드는 애"는 이미 자동 |

즉 **"영상 제작 에이전트"는 이미 존재**한다. 새로 만들 가치가 큰 건 **① 시장조사(스카우트)** 와 **④ 매니저(관리)** 다.

---

## 1. 역할(에이전트) 정의

> 여기서 "에이전트"는 클로드코드 개발 도우미가 아니라, **서비스 안에서 자동으로 도는 백엔드 역할**(cron 스케줄 / 워커 루프)이다. 서로는 **DB 와 텔레그램**으로 연결된다.

### ① 스카우트 — 시장조사 (신규)
- **목적**: 만들 만한 상품 후보를 자동으로 찾아 `products` 에 `status='candidate'` 로 적재.
- **입력**: 쿠팡파트너스 API(베스트/골드박스/카테고리 검색), 기존 products(중복 제외), 카테고리 화이트리스트.
- **처리**: 후보 필터(카테고리 적합·가격대·중복 제외) → 딥링크 생성(`coupang_partner_url`) → products insert.
- **출력**: 새 후보 N개 + 텔레그램 "오늘 후보 N개 올라왔어요".
- **트리거**: 매일 아침 cron (예: 08:00 KST).

### ② 플래너 — 기획/카피 (기존 확장)
- **목적**: 후보 → 어떤 **번호/템플릿/후킹**으로 갈지 정하고 카피 생성.
- 이미 `ai.ts` 에 카피 생성이 있음. 확장: 템플릿 자동 선택, A/B 훅 2안, 카테고리 자동 보정.
- **트리거**: 영상 생성 요청 시 호출(현재도 그렇게 동작).

### ③ 렌더러 — 영상 제작 (완성, 변경 없음)
- pending 감시 → Remotion 렌더 → 드라이브 업로드(`N번_제품명.mp4`) → 텔레그램 완료 알림.

### ④ 매니저 — 전체 관리 (신규)
- **목적**: 하루 계획 + 성과 리포트 + 파이프라인 지휘.
- **아침**: 오늘 만들 개수 결정(예: 후보 상위 3개) → 번호 부여 → `video_items(pending)` 생성(→ 렌더러가 처리).
- **저녁**: `click_logs` 집계 → "오늘 클릭 상위 번호 / 이번주 성과" 텔레그램 리포트.
- 성과 낮은 번호는 `landing_visible` 끄기 제안 등.
- **트리거**: cron 2회(아침 계획 / 저녁 리포트).

## 2. 데이터 흐름 (승인 게이트 방식 기준)

```
[cron 08:00] 스카우트 → 쿠팡API → products(candidate)
                     └→ 텔레그램 "후보 N개, 만들까요?"
        │
        ▼ (텔레그램에서 승인 / 후보 선택)
[매니저] 승인 후보 → 번호부여 → video_items(pending) + 플래너 카피생성
        │
        ▼
[렌더 워커] pending 감지 → 렌더 → 드라이브 업로드 → completed → 텔레그램 "완료"
        │
        ▼ (사장님이 mp4 받아 릴스/틱톡/쇼츠 업로드, 캡션에 프로필 링크)
[공개 사이트] 방문자 번호검색 → /api/click → click_logs 기록
        │
        ▼
[cron 20:00] 매니저 → click_logs 집계 → 텔레그램 성과 리포트
```

## 3. 자동화 수준 (핵심 선택지)

| 방식 | 내용 | 장단점 |
|---|---|---|
| **A. 승인 게이트** (추천 시작점) | 스카우트는 후보만 올림. 영상 제작은 사장님 승인 후. | 품질·브랜드 안전, 이상한 상품 거름. 사람이 최종 결정 |
| **B. 완전 자동** | 스카우트→매니저가 매일 N개 알아서 제작·업로드 준비까지. | 손 안 대도 굴러감. 품질 통제는 약함 |

> **추천**: 처음엔 A로 운영하며 신뢰를 쌓고, 원하면 **플래그 하나로 B 전환**. (코드는 A/B 둘 다 지원하게 설계)

## 4. 쿠팡파트너스 API — 먼저 확인할 것

- 보유 키(access/secret)로 어떤 엔드포인트가 되는지 **실제 호출 검증부터** 한다.
  - **딥링크 생성 API**: 대체로 가능 → `coupang_partner_url` 자동 생성에 사용.
  - **상품 검색 / 베스트 / 골드박스 API**: 파트너스 승인 등급에 따라 열려 있을 수도, 막혀 있을 수도.
- 만약 상품검색이 막혀 있으면 대안:
  1. (현행) 상품 URL 을 사장님이 붙여넣으면 스카우트가 정제·딥링크화.
  2. 골드박스 등 공개 딥링크 활용.
  3. 카테고리 베스트 수집(약관·robots 확인 필수).

---

## 5. 구현 단계

- **Phase 1 — 스카우트**: 쿠팡 API 검증 → 후보 자동 적재 → 텔레그램 승인.
- **Phase 2 — 매니저**: 아침 계획 자동화 + 저녁 성과 리포트.
- **Phase 3 — 플래너 고도화**: 템플릿 자동 선택, A/B 훅 2안.
- **Phase 4 — (선택) 완전 자동 플래그**.

---

## 6. 인프라 / 운영

- **cron**: 스카우트·매니저 같은 가벼운 잡은 Vercel Cron(무료) 또는 상시 워커 PC 스케줄러.
  - ⚠️ **렌더는 서버리스 불가** → 렌더러는 계속 로컬/상시 PC 워커에서.
- **워커 인스턴스는 하나만** (드라이브 폴더 중복 방지).
- **시크릿**: 쿠팡 키는 `.env.local` / Vercel 환경변수에만. **커밋 금지 원칙 유지**.
