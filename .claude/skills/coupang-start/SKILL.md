# 쿠팡 시작 (이어받기 절차)

사장님이 Claude 계정을 바꿨거나 새 세션을 연 상황이다. 아래를 순서대로 하고, 끝에 한국어로
짧게 브리핑한다. 사장님께 되묻지 말고 할 수 있는 건 다 한다. 막히는 단계는 건너뛰고 브리핑에
"사장님이 할 일"로 적는다. 비밀값은 출력하지 않는다.

## 1. 기억 불러오기
- `CLAUDE.md`(운영 규칙), `docs/handoff/CURRENT.md`(지금 상황), `docs/growth-plan.md` 상단 블록을 읽는다.
- 절대 규칙(쿠팡 API 위반 2회, 본인 클릭 금지, 고지, 로그인·동의는 사장님이 직접)을 이번 세션 내내 지킨다.

## 2. 저장소·브랜치 맞추기
- 작업 브랜치는 `claude/blissful-noether-ofm9ww`, 운영 브랜치는 `claude/coupang-partners-shortform-hinfcb`.
- `git fetch` 후 작업 브랜치로 체크아웃하고 원격 최신으로 맞춘다(커밋 안 된 변경이 있으면 지우지 말고 보고).
- 두 브랜치가 같은 커밋인지 확인한다. 다르면 브리핑에 적는다(임의로 강제 push 하지 않는다).
- PC 에서 처음이면 `npm ci` 와 `node scripts/gen-version.mjs` 로 점검 준비를 한다.

## 3. 자동화 상태 점검 (읽기만)
GitHub 도구(MCP 의 actions_list / get_job_logs, 또는 `gh api`)를 쓸 수 있으면:
- `render.yml`, `scout.yml` 최근 실행 3개의 성공/실패. 실패면 로그에서 원인 한 줄.
- `diag.yml` 을 `script: publish-status` 로 실행해 최근 3일 영상별 유튜브·인스타 결과, 정책 차단,
  대기열 수를 본다(읽기 전용 진단). 본인 상품(근사장) 영상이 섞여 나갔는지도 본다.
- GitHub 도구가 없으면 이 단계는 건너뛰고 "claude.ai 설정 → 커넥터에서 GitHub 연결 필요"라고 적는다.

## 4. 예약 루틴 복구
루틴(예약 작업)은 계정에 묶여 있어 계정이 바뀌면 사라진다. 루틴 도구(list_triggers / create_trigger,
또는 /schedule)를 쓸 수 있으면 목록을 보고 **없는 것만** 만든다(중복 생성 금지):
- "주간 판정표 (새 전략)" - 매주 월 09:47 KST (`CRON_TZ=Asia/Seoul 47 9 * * 1`). 문구는 CLAUDE.md.
- "30일 사업 방식 판정 (11/1)" - 2026-11-01 09:30 KST 1회. 이미 지난 날짜면 만들지 말고 브리핑에 적는다.
만들 수 없으면 브리핑에 "루틴 2개 다시 만들기 필요"로 적는다.

## 5. 브리핑 (한국어, 짧게)
- 지금 상황 3줄(CURRENT.md 요약)
- 자동화 상태: 렌더·스카우트 정상 여부, 최근 3일 발행 편수
- 이번에 내가 맞춘 것(브랜치, 루틴 등)
- 사장님이 할 일(답 기다리는 질문, 막혀서 직접 해야 하는 것)
- 다음에 할 일 제안 1~2개 - 승인이 필요한 변경은 제안만 한다

## 6. 마무리
- 바뀐 상황이 있으면 `docs/handoff/CURRENT.md` 를 고쳐 두 브랜치에 커밋·push 한다
  (커밋 메시지 한국어). 고칠 게 없으면 커밋하지 않는다.
